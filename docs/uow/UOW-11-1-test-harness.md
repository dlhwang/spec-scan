# UOW-11-1: 테스트 하네스 구축

## Goal (목표)
각 UOW 개발 시 그래프 손상 및 커버리지 역행(Regression)을 사전에 감지하고, 수정된 그래프 구조가 규격에 맞게 작동하는지 지속 보증할 수 있는 Golden Graph Test 및 Candidate Extraction 테스트 환경을 견고히 구축한다.

## 1. 문제 증거
현재 Visitor의 수정 사항이 기존에 잘 검출되던 검증 규칙들의 결과 그래프를 깨뜨리는지 수동으로만 확인해야 하거나, 테스트 코드 파싱 검증이 특정 표현식 단위로 쪼개져 있어 거시적인 그래프 형상 검증이 까다롭습니다.
안정적인 리팩토링을 위해 그래프의 스냅샷을 고정하고 비교 검증하는 체계가 결여되어 있습니다.

## 2. 지원 대상 코드 패턴
* 테스트 대상 자바 소스 파일 묶음 및 기대하는 JSON 포맷의 그래프 구조 데이터셋.

## 3. 현재 그래프
* 개별 임의 검증만 수행 중.

## 4. 기대 그래프
* 입력 코드 소스 실행 -> 생성된 JSON Graph -> Golden Snapshot JSON Graph와 exact match 또는 의미적 동형 검증 통과.

## 5. 수정 책임 클래스
* 신규 테스트 지원 클래스 추가 (예: `io.atworks.specscan.analysis.support.fact.GoldenGraphTest`)

## 6. 비대상 범위
* GraphRule에 대한 전수 검증은 제외하며, 오직 Visitor가 만드는 Fact Graph 및 생성된 Candidate의 정보 정확성(SourceRange, Variable Reads, Edge Type 등)만 검증합니다.

## 7. 테스트 케이스
* 사전에 고정해 둔 10개 이상의 값 검증 기본/복합 패턴 코드를 대상으로, 코드 변경 후에도 그래프 노드/엣지 정보가 Golden JSON 스냅샷과 일치하는지 비교하는 테스트 케이스 구동.

## 8. 완료 기준
* 소스 파일 입력을 받아 JSON 그래프 결과와 기대 파일을 자동 매칭 비교하는 테스트 스위트가 동작합니다.
* 변경 사항이 있을 때만 Golden 파일을 갱신(Update)하는 도구를 제공합니다.

## 9. 성능 및 호환성 영향
* 빌드 단계에서 추가적인 파일 I/O 및 JSON 비교 오버헤드가 발생하지만, 빌드 안정성을 크게 향상시킵니다.
