# AI-DLC 지침 체계 비교 및 하네스 엔지니어링 적합성 평가 리포트

본 평가는 `auto-oas` 프로젝트의 거시적 프로세스를 지배하는 **표준 AI-DLC 지침 (`.agents/.aidlc/aidlc-rules`)**과 단일 세션의 기획/실행을 정밀 통제하는 **세션 수준 실행 지침 (`agent-docs`)**을 비교 분석합니다. 

특히, **사용자의 직관적 의도(Vibe)를 정교화하여 모호성을 보완하고, 테스트/검증 환경(Harness Engineering)을 통해 품질을 입증하는지**를 중심으로 평가를 진행하였습니다.

## 🔎 2. 세부 지침 분석 및 평가 내용

### ① 표준 AI-DLC 지침 (`.agents/.aidlc/aidlc-rules`)
* **강점 (거시적 통제력)**:
  - 프로젝트 전체 생명주기(Workspace Detection ➔ Reverse Engineering ➔ Requirements ➔ User Stories ➔ Application Design ➔ Build & Test)를 아우르는 **거대 거버넌스(Governance) 프레임워크**로서 매우 훌륭하게 작동합니다.
  - 요구사항 추적 매트릭스나 아키텍처 디자인 단계의 논리적 경계 정의가 문서화 수준에서 잘 설계되어 있습니다.
* **약점 (실행 정밀도 부족)**:
  - 실제 에이전트가 코드를 수정하고 테스트하는 미시적인 턴(Turn) 단계에서, 에이전트가 마주치는 세부 에러나 모호함을 동적으로 해소하는 로직이 부족합니다.
  - '구현 완료'에 대한 판단을 에이전트의 주관적인 선언에 의존하므로, 하네스 엔지니어링 관점에서의 엄격한 테스트 락(Lock) 및 강제 검증 수단이 약합니다.

### ② 세션 수준 실행 지침 (`agent-docs`)
* **강점 (초정밀 하네스 및 의도 제어)**:
  - **모호성 차단기**: `specs/deep-interview-[slug].md`를 통해 사용자의 바이브(의도)를 고도로 구조화된 기술 옵션(Option A/B)으로 구체화하고 명세 자산화합니다.
  - **다단계 합의 기획**: Critic(구체성 비판)과 Architect(도메인 적합성 검증)가 계획을 통과시키고, 최종 기획서에서 기각 대안과 인텐트 일치성을 매핑(`Intent Reconciliation`)하여 설계 결함을 사전 필터링합니다.
  - **동적 하네스 루프**: `goals.json` 내에 구체적 Assertions 성공 로그가 입증(`evidence`)되어야만 완료 상태를 부여하고, 실패 시 우회 없이 **하위 블로커 목표를 동적으로 주입**하여 격리 해결하는 강인한 하네스 엔지니어링 구조를 가집니다.
* **약점 (거시 맥락 부재)**:
  - 에이전트의 미시적인 상태 제어에 집중되어 있어, 프로젝트가 브라운필드인지 그린필드인지에 대한 거시적 탐색이나 컴포넌트 간 비즈니스 트랜잭션의 역공학 분석 같은 거시적 맥락은 다루지 않습니다.

## 📝 3. 종합 평가 및 결론 (Summary & Verdict)

> [!IMPORTANT]
> **종합 의견: 상호 보완을 통한 완전한 AI-DLC의 완성**
> - **표준 AI-DLC 지침**은 에이전트 개발 수명주기의 **'골격(Skeleton)'**을 제공하며, **세션 수준 실행 지침**은 그 안에서 에이전트가 오작동 없이 작동하도록 제어하는 **'신경망(Neural Network)'**의 역할을 합니다.
> - 사용자의 다소 모호한 바이브를 놓치지 않고 설계로 정교화하며, 빌드/테스트 하네스로 이를 끝까지 입증하도록 강제하는 실행력 측면에서는 **세션 수준 실행 지침(agent-docs)**이 압도적으로 우수하고 정밀하게 설계되어 있습니다.
> - 따라서, 실제 개발 프로세스 가동 시 **표준 AI-DLC의 Inception 및 Construction 페이즈 내 단계별 실행 규칙으로 세션 수준 실행 지침(Deep Interview, Consensus Planning, Goal-Driven Execution)을 결합하여 가동하는 것**이 가장 이상적이며 강력한 하네스 엔지니어링을 실현하는 방법입니다.
